# Re-Audit & Before/After — Student Academic OS

**Date:** 2026-08-08
**Method:** Direct evidence — full source reads, real `npm run build` + `vitest run`
output, real Postgres (Docker) migration verification, live deploy checks against
`https://student-academic-os.pages.dev`. Supersedes `QA-AUDIT-2026-08-07.md` (the "before").
Every claim below is from an observed run, not a code read alone.

**Architecture in one line:** React 18 + Vite + TypeScript **offline-first PWA**
(Dexie/IndexedDB), thin Supabase PostgreSQL backend reached only via SECURITY
DEFINER RPCs (anon key + RLS), deployed as a static site on Cloudflare Pages with
GitHub Actions CI/CD. **No custom server.**

### Database (Section 7) — verified on real Postgres (Docker, Postgres 16 + Supabase roles)
Migrations `0001→0004` applied cleanly:

- `access_keys` indexes are now only `access_keys_pkey` + `access_keys_code_key`
  (redundant `access_keys_code_idx` gone).
- `admin_actions` table: RLS enabled, **zero policies**, no grants to `anon`/`authenticated`.
- Behavior: mint + deactivate + reactivate → 3 audit rows with **masked** target
  codes; owner `admin_list_actions` returns them; student call → `UNAUTHORIZED`;
  direct anon SELECT → `permission denied`.
- Re-running `0004` is idempotent.

### Networking (Section 8)
- `public/_headers` ships to `dist/_headers` on every build (verified post-build).
  CSP: `default-src 'self'`, `script-src 'self'` (no inline scripts in the built
  HTML — verified), `connect-src 'self' https://*.supabase.co wss://*.supabase.co
  https://fonts.googleapis.com https://fonts.gstatic.com`, `frame-ancestors 'none'`,
  `style-src 'self' 'unsafe-inline'` (required by React inline styles), plus
  `nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`,
  `Permissions-Policy`, COOP/CORP.
- The live Supabase host (`eyuevplcsfrgyqmzunni.supabase.co`) is covered by the
  `*.supabase.co` wildcard.
- Header-based (not `<meta>`) so `vite dev` HMR is unaffected.
- `scripts/verify-live-deploy.cjs` now asserts the security headers on the live
  URL (CSP present, connect-src scoped, no unsafe-inline, nosniff/referrer/frame).

## Residual (tracked, non-blocking)

- **Main chunk > 500 kB** (Vite warning) — optional `manualChunks` split.
- **CORS allow-list** on the Supabase project is still the permissive default `*`;
  the exact Dashboard steps to lock it to the Pages origin are documented in
  DEPLOY.md. Safe as-is (RLS + access-key self-auth), tightening is one click.
- **Live header check** — **resolved 2026-08-08 (evening).** Rebuilt + direct-deployed
  via `wrangler pages deploy` (the working method); `verify-live-deploy.cjs` now
  reports **15/15** against the live URL, CSP + all headers served. One verifier
  assertion bug found & fixed (CSP inline-script check was scanning the whole
  header, so the legitimate `style-src 'unsafe-inline'` caused a false failure).
- **Client RPC timeouts/backoff** on `adminKeys.ts` calls — NETWORK error surfaces
  but no retry.
- **`admin_generate_key` expiry** — a past `expires_at` mints an already-expired
  key (no server-side reject).
- **Monitoring** — recommendation only (Supabase `app_errors` table first, Sentry
  later); not implemented until the user opts in.
- **Deactivate ≠ kick out** — offline-first by design; residual risk low (data is local).
- **Auto-backup** (scheduled) still open; manual export/restore works.
- **Staging/prod separation** — one Supabase project serves both; acceptable for a personal tool.
- **Repo remote name** is `COMPANION` — cosmetic, not functional.
- **CI deploy step** — **open (blocked on repo secrets).** First CI run of the
  `cloudflare/pages-action@v1` deploy step failed *before* any upload (no failed
  deployment record on the Pages project), i.e. auth/project-lookup stage. The
  direct-upload path (wrangler OAuth) works, so the target/account/build are
  healthy; the CI-specific `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID`
  secrets are the suspect. Deploy-step logs need GitHub admin rights (403 via
  API for this session), so the exact error message still needs a look from the
  Actions web UI. The Node-22 CI runtime fix (`1129c34`) landed and the
  `Test & build` job now passes.
